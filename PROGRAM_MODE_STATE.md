# Program Mode state

The coordinator owns one state value. `CLOSED` permits ordinary keys. `OPEN` means Contact ID 627 was seen; it has an operation id only when that operation explains the report. `DOUBT` has a generation, the operation id if one holds the keypad, and `saw_627`, which records whether any 627 arrived since this doubt began. Neither an issue deletion nor a reconnect is evidence that the panel left Program Mode.

The state transition function takes every event. A change also advances a revision used by each key gate and by the repair confirm. An operation receives a unique id; its entry keys require its own unchanged doubt, and its menu keys require its own unchanged `OPEN`. An operation explains a 627 in exactly two cases: a guided operation whose entry keys are all acknowledged, while the state is its own `DOUBT`; and an installer operation with at least one acknowledged key. A 627 that no operation explains binds to nobody, and the next key of every operation stops with the Program Mode lost refusal. Only a `^03` response `00` counts a key as written; an overrun or other refusal does not count, including during retry backoff.

## Write gate

Every key from guided programming, confirmed installer send, arm, disarm, bypass and ordinary send crosses one gate immediately before its `^03` frame is written, under the client's command lock. Each retry crosses the same gate. The gate checks the operation's starting TPI session revision, a fresh `%00` report for the key's partition on that revision, disarmed state when that operation requires it, and the Program Mode state for this operation's next key: its own `DOUBT` for guided entry, its own `OPEN` for guided menu entry, or `CLOSED` for ordinary keys. Confirmed installer keys follow the state owner's installer rule. A failed check interrupts the operation through the state owner. A release, drop, reconnect or resume changes the session revision, so a held operation cannot write on a later session.

| Event | CLOSED | OPEN | DOUBT |
|---|---|---|---|
| Operation start | Guided or installer: create a new doubt generation with operation id; ordinary: unchanged | Refuse guided or ordinary; installer keeps the unsafe state and binds its id | Refuse guided or ordinary; installer keeps the unsafe state and binds its id |
| Key write | Ordinary allowed through the write gate; guided requires its own durable doubt first | Guided menu keys require the operation whose 627 opened this state and an unchanged revision; confirmed installer keys require their active holder | Guided entry keys require the operation that raised this doubt and an unchanged revision; confirmed installer keys require their active holder |
| No key sent | Unchanged | Unchanged | `CLOSED` when this operation raised the doubt (the event's generation is the current one), still holds it, and no 627 was seen; any other doubt stays |
| 627 | New `OPEN` with no operation owner | New `OPEN`; a guided operation's binding is invalidated, an installer operation with an acknowledged key keeps its binding | `OPEN` bound to the holder only if it explains the report, otherwise `OPEN` without an owner; `saw_627=true` |
| 628 | `CLOSED` with a new revision | `CLOSED`; the binding ends, so the next key of any operation stops with the Program Mode lost refusal | `CLOSED`; the binding ends, so the next key of any operation stops with the Program Mode lost refusal |
| Armed report for a tracked partition | Unchanged | Unchanged | `CLOSED` only if `saw_627=false`, no operation id is bound and no operation holds the keypad |
| Disarmed report | Unchanged | Unchanged | Unchanged |
| Disconnect | Unchanged state, new revision; all partitions become unknown | `DOUBT` with `saw_627=true`, new revision; all partitions become unknown | Preserve generation, operation id, and `saw_627`; new revision; all partitions become unknown |
| Reconnect | Unchanged state, new revision; partitions remain unknown until their own fresh reports | Treat as disconnect before reconnect | Unchanged state, new revision; partitions remain unknown until their own fresh reports |
| Reload or restart | Restore durable state; all partitions unknown | Restore as `DOUBT`, preserving `saw_627` | Restore generation and `saw_627`; old operation id cannot authorize new keys |
| Repair confirm | Refused: nothing to confirm | `CLOSED` only if idle and the flow's generation and revision match | `CLOSED` only if no operation holds the keypad and the flow's generation and revision equal the current ones; otherwise refused as stale, or as held when an operation holds the keypad |
| Operation end | Unchanged | A guided or installer operation becomes `DOUBT` with `saw_627=true` unless 628 arrived; an ordinary operation leaves `OPEN` | A guided or installer operation clears its id but preserves generation and `saw_627`; an ordinary operation leaves `DOUBT` |

The doubt is raised for keys about to be typed. An operation that ends without an acknowledged key or an unacknowledged write applies No key sent before it ends, unless a 627 was seen. A key with no acknowledgement can have reached the panel and therefore keeps doubt; a definite module refusal cannot have reached it and does not count as written.

The doubt and its generation and `saw_627` are saved in the integration's own Home Assistant storage before the first key, with that save awaited before the key phase and read back inside the save chain, so a later transition that overwrites the record does not make the read-back fail. The repair issue mirrors them for display and carries the generation and revision captured by its confirm flow, which are renewed with every change. An active operation's doubt appears in the System trouble diagnostic as installers_mode, not as an ERROR repair; if it ends in doubt, the ERROR repair appears. The repair registry's delayed save is never the safety store. A stale flow or a flow submitted while the keypad is held aborts and leaves doubt intact.

A transition that makes the state less cautious, including No key sent and repair confirmation, is saved and read back before changing the in-memory state. A transition that raises doubt is saved before any following key. Restoring after a crash uses the last verified durable state; a completed `CLOSED` save cannot leave an older doubt visible in memory or on restart.

After any disconnect or reload, each partition's arm state is unknown until its first fresh panel report: the partition's alarm entity reads unknown, and a guided entry, an arm, a disarm, a bypass and an unconfirmed send refuse it. The integration asks for the report when a session is established, and again before a keypad use that needs it, with a bounded wait. The request is the module's change-default-partition command `^01` naming the partition, the one TPI command that names a partition without typing a key; the module is then returned to partition 1, which is its default. Whether the EnvisaLink answers it with a keypad update has not been verified on hardware. A partition that stays silent is never treated as disarmed or as absent: the refusal names it and says what to do next. A user may settle an ended doubt by checking the physical keypad, leaving Program Mode with `*99` if necessary, and confirming the current repair. A later 628 settles it automatically.
